## 結論
学習教材として有望で、形成的パイロットを行う価値がある。探索→照合→判断→即時解説、安全事例、探索ログ、別フォームの前後テストが強み。ただし現実への転移・長期保持・3D固有の効果は未実証。本実験前は教材の正確さ、判断根拠の測定、操作と保存の確実性を優先する。

## P0：本実験前に優先

1. **教材の断定表現と正解根拠**（scenarios/*.ts、lib/pretest.ts、lib/transferTest.ts）
   - HTTPS、表示上の送信元、リンクなし、自分の行動との一致は、安全性の十分条件ではない。「この事例では正常」と一般的な判断方法を分ける。
   - S1の在宅予定は実際の在宅や配達応答の証拠ではない。疑う材料と断定根拠を区別する。
   - 「URL末尾」はパスやクエリと混同しやすい。ホスト名と登録ドメインを具体例で示す。.xyz/httpだけで詐欺と決める学習を避ける。
   - PRE_S3/POST_S2/POST_S3等の架空サービスには公式ドメインの照合基準を提示する。解説でのみ正規と断定しても解答時の根拠にならない。
   - 公式アプリや既知の連絡先を自分で開いて確認する行動へ解説をつなぐ。[3][4]
   - 完了条件：各問の正解が出題情報から説明でき、単一の表面的特徴を安全の保証にしない。

2. **ヒント後の再調査**（ConfidenceSlider.tsx、GameClient.tsx、gameStore.ts）
   - 判定画面のヒントは見比べるよう促すが、調査へ戻る操作がない。戻る導線を設け、回答候補とヒント履歴を保持する。
   - 再調査を含むRTと最初の判定表示時刻の意味を定義し、既存RTの定義を無言で変更しない。
   - 完了条件：ヒント→再調査→再判定ができ、調査・ヒント・RTログが整合。

3. **保存・参加者・版管理**（logger.ts、gameStore.ts、ResultClient.tsx、export_firestore.py）
   - survey/scoreとstore.phaseの不一致を修正。一時的なバックグラウンド化をdropoutPhaseだけで離脱と決めない。
   - 保存待ち/同期済み/失敗を区別し、オフライン→復帰→CSVでデータを照合する。参加者の進行を通信待ちで止めない。
   - schemaVersion/contentVersionを保存し、問題・UIの変更版を識別する。
   - 再読込時は復元か明示的再開始かを決め、途中データと完全なデータを区別する。
   - priorPlaysは端末カウンタであり本人の再参加ではない。共用端末では自動除外に使わない。現exportはtestRunのみ自動除外し、再参加・完了条件は分析側で未確定。
   - 完了条件：前6・本編6・後6・SUS10の一致、欠損/中断の識別、共用端末の別参加者を保持。

4. **操作と検証環境**（FPSControls.tsx、Room.tsx、eslint.config.mjs）
   - 学習課題と別の短い練習で移動・視点・調査・判定を確認し、分析対象から除く。
   - 移動/スティック旋回をdeltaに対応し、非探索中やblur時の入力を整理する。毎フレームのVector3生成は性能測定と併せて最小修正。
   - Android Chrome/iOS Safariで横向き・文字・スクロール・中断復帰・酔いを確認する。
   - lint設定とbuild停滞を解消し、配信物で通し確認する。
   - 完了条件：FPSによる移動速度差を解消、画面切替で移動停止、初見完走と所要時間を記録。

## P1：学習・効果測定の改善

5. **対象通知と根拠を確認する**
   - 現状は詐欺あり/なしだけなので、別の通知を疑っても正解になる。viewedAllRelevantも開いた証拠であり理解の証拠ではない。
   - 対象通知・主な根拠の選択を候補にする。まずパイロットで回答後の聞き取りを行い必要性を判断する。
   - 選択肢による誘導と時間増加に注意し、採用する場合は判断後に収集、RT終点と版を管理する。

6. **復習とヒント**
   - 結果画面のカードは正解分のみ。誤答問題も復習可能にし、誤答を優先する。
   - ヒント-10点は正解15点に対して大きい。支援回避を促す可能性があるため、無罰化か自力/支援あり別表示を検討する。現状の使用率を純粋な難易度と解釈しない。
   - 解説は通知の主張・比較した事実・安全な確認行動を対応させる。

7. **主張と指標を本実験前に固定する**
   - 主指標案は前後の判断正確性。見逃し率と誤警報率を分け、フォーム/項目差・提示順を考慮し、効果量と不確実性を示す。
   - 6問では1問で約16.7ポイント、詐欺/安全各3問では約33.3ポイント刻み。個人別d′や項目識別力は不安定。0/1率の補正を事前指定し、探索的に扱う。
   - 1〜5の確信度は確率尺度ではない。Brier scoreへ無根拠に変換せず、正誤別確信度・高確信誤答を確認する。
   - RT短縮だけを成功としない。探索慣れ・端末差・読み飛ばし・中断・確信度操作が混ざる。正答率を併記する。
   - 本編は全て詐欺と答えても4/6=66.7%。正答率だけで判断の偏りは評価できない。
   - 単群前後比較を維持する場合、練習効果等とゲームの因果効果を分離できない限界を明記。3D優越性・長期的被害抑制は主張しない。
   - A/Bのタグ一致は等価性の証明ではない。ランダム割付は人数均等を保証しない。家族なりすまし等、学習課題と類似した問題を含むため、近い転移として整理する。
   - SUSは操作性の指標で学習効果ではない。改変した日本語項目の出典・変更を明記し、妥当性確認済みとは断定しない。

## 実施順

P0 → 少人数（例5〜8名）の形成的パイロット → 改善 → 問題/ログ/分析条件の固定 → 本実験。
少人数パイロットは使いづらさ・誤解の発見用で、効果や難易度の統計的確定には不足。所要時間、操作補助、判断理由、ヒント後の行動、保存の一致を確認する。
約30名の本実験では複雑なモデルや細かな属性比較を主目的にしない。将来の非3D教材比較・遅延テスト・初見場面での確認行動評価は別途設計する。
GLB、効果音、新ステージ、大規模リファクタリングは後回し。操作・読解の明確な問題に効く場合のみ優先する。
