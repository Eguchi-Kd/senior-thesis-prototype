## 3. 新たな実装・運用上の懸念

### T1【高・ロジック再現】解除ボタンでURLの test=1 が残る

`app/page.tsx` の exitTestMode はlocalStorageと表示・ストアを更新するがURLを変更しない。そのまま「はじめて遊ぶ」を押すとreset→resolveTestModeが現在の `?test=1` を読んで再びtrueを保存する。画面上では解除したのに、収集データが試験扱いで除外される。

実関数で `URL_TEST true → AFTER_BUTTON_SAVED false → NEXT_RESET_RESOLVE true` を再現した。解除時にURLの試験指定も除く／0にするなど、表示と次のresetの判定を一致させる。修正後は「test=1を直接開く→解除ボタン→開始→保存」の経路を試験する。通常URLでの解除とは別ケース。

### T2【高・合成データで再現】異なる版を既定操作で合算できる

`analysis/select_sample.py` の `--content-version` は任意。各セッションのcontentVersionsSeenが1個でも、別々のcontentVersionを持つ2人は既定で両方採用され、analyze_primary.pyも合算する。合成2件で採用2件、解析終了0を確認した。分析計画の「異なる版を合算しない」が保証されていない。

本収集用では対象版を必須化するか、複数版検出で止め、解析側にも単一版の確認を置く。パイロット手順のコマンド例にも版指定を入れる。項目定義と版の不一致をWARNだけで済ませ、現行items.jsonで旧版を採点しない。

### T3【中・合成データで再現】不正な数値でvalidator全体が停止する

`analysis/validate_export.py` の `x != int(x)` はNaNでValueError、InfinityでOverflowErrorになる。SUSに合成値を入れて確認した。通常UIでの発生を示すものではないが、破損データを除外するための検証器が止まると、正常な他の参加者まで選定できない。有限性を確認してから整数化し、対象sessionのERRORにする。position、イベント時刻等の変換も同じ観点で確認する。

## 4. 教材全体に共通する評価基準

各問題を「提示情報だけで正答を説明できるか」「目標の操作を本当に必要とするか」「ヒントが適切な情報に導くか」「解説が別の場面で使える確認方法を教えるか」で評価した。

全テスト12問に個別ヒントはなく、正誤・解説は結果画面で提示する。事前テストから正解を教えない設計として適切。本編では正解・不正解の両方で解説と学習ポイントが表示されることも確認した。

共通の改善点：

1. **矛盾と不審を区別する。** 予定と違う・知らない番号というだけでは偽物確定ではない。物語上の正答は維持しつつ、現実の行動は「保留して独立した経路で確認」と教える。
2. **既知の事実と誘導文を分ける。** 公式情報の比較基準は受信メッセージ自身が主張しているものではなく、既に確認した情報であると示す。
3. **ドメインの説明を具体化する。** URL末尾はパス（/signin等）でありドメインではない。「ホスト名の右端」も末尾2語を拾えば常に正しいという意味ではない。公式名との完全一致、または直前がドットのサブドメインという境界を例で示す。「持ち主」より「登録ドメイン」「公式として確認したドメイン」とする。現在の単純なURL例での判別は合っているが、全URLを説明する一般則としては省略がある。
4. **表面だけで解ける偏りを抑える。** 本編のURL付き詐欺（S1/S4）は両方http、正常のURLはhttps。テストにもhttps詐欺はあるが、本編でhttpだけを目印に学習する余地がある。少なくともS4をhttpsの例にする候補を検討。
5. **中高生の前提知識を確認する。** 海外赴任・示談金・銀行認証・カード・サブスクは、未経験者では読解・生活経験のテストになり得る。題材全交換は不要だが、用語の説明とパイロットの聞き取りが必要。

通知のリンクに頼らず、普段の公式アプリやブックマーク等から確認する学習ポイントは、警察庁の対策と整合する。[警察庁：フィッシング対策](https://www.npa.go.jp/bureau/cyber/countermeasures/phishing.html)

### S2 家族からの緊急連絡（id=2、正答＝詐欺）【要修正・高】

- 目標：家族の予定との矛盾、緊急送金・口止め・登録外番号の複合判断。
- ヒント：家族の予定との比較を促す方向は適切。

- 学習ポイント：登録済み本人番号へのかけ直しは適切。「家族や警察」の両方を同じ本人番号で扱う表現は、家族は登録済み番号、警察は自分で調べた代表番号、と分けると明確。

### S3 ウイルス感染の警告（id=3、正答＝詐欺）【要修正・高】

- 目標：偽警告・電話誘導への対処、契約情報との照合。
- ヒント：PC/ソフトの契約メモへ誘導するが、警告はスマートフォン上にあり、特定の有料ソフト名も契約の主張もない。PCで契約していないことはスマホ警告の真偽と直結しない。OS標準保護でも正規警告はあり得る。
- 解答・解説：突然の感染表示から電話を急がせる詐欺、という判定は妥当。電話せず画面を閉じる方針も適切。[IPA：サポート詐欺対策](https://www.ipa.go.jp/security/anshin/attention/2024/mgdayori20241119.html)
- 最小案：ブラウザ閲覧中の警告という状況を本文で明示し、メモを同じ端末の情報に揃える。照合課題にするなら「端末に保存してある公式の対処手順」と警告の要求を比較する構成が候補。契約なしを偽物確定の根拠にしない。
- ヒント案：「警告はどの画面に出て、何をするよう求めていますか。メモの対処方法と比べよう」。解説は「ブラウザの突然の表示／電話要求／独立確認」の順へ。
- 再起動は補助手順としてよいが、端末に合った手順を使う。「全ての警告は閉じれば解決」と一般化しない。

## 7. 問題セットとしての偏り・測定上の懸念

### 7.1 フォームA/Bの等価性

F2はURL構造の難しさが非対称。S2は二段階認証とパスワード変更で技能が違う。F1もニセ警察と家族なりすましで必要知識が異なる。さらにフォームBの家族・パスワード変更は本編S2/S102との対応が強い。カウンターバランスは有効だが、個別フォームの等価性を保証しない。

優先案：F2の構造を揃える。S2は学習目標を揃えた別文脈の問題にするか、現在の異質性を明示し割付順別に報告する。問題数を増やす前に内容の対応表を整える。本編6問にはサポート詐欺があるが、テストに直接対応する問題はない一方、テストの未払い請求・認証コードは本編で直接扱わない。全手口の習得度を測るテストではなく、選定した判断課題の成績である。

### 7.2 「身に覚え」の近道

テストの正常6問は全て、自分の契約・注文・操作の裏付けが明示されている。詐欺6問にはそれに相当する「実際に注文を待っている」「本当に契約中」といった前提整合がほぼない。transferTest.tsのコメントがいう「身に覚えのある詐欺」は十分に実現されていない。

最小案として、A/Bの詐欺F2の両方に「実際に利用しているサービスから、いつもの案内に似た通知が来た」という文脈を追加し、身に覚えがあっても公式ドメインの比較が必要な条件にする。項目構成の変更はパイロット前に行い、事後に成績が良くなる問題を選び直さない。

手がかりの量と受け手の文脈への整合は難易度評価に関係する。ただしNIST Phish Scaleはフィッシングメール向けで、本ゲームの安全問題や3D探索の妥当性を保証する尺度ではない。[NIST Phish Scale User Guide](https://csrc.nist.gov/pubs/tn/2276/final)

### 7.3 表示と世界設定

- SMSにメールアドレス、アプリ通知にメール送信元、振込口座/電話番号に「リンク先」ラベルが付く（GameClient/QuizRunner）。URL・番号・口座・送信元を学ぶ教材では混同の原因になる。データの種別に応じて「連絡先」「振込要求」等へ表示する小修正が望ましい。実URLはp要素表示で、教材内からクリックして移動する実装ではない。
- 6/29（日）、7/8（火）等は2025年の曜日配置で、周辺ポスターは2026年。11月のS4は2026年と整合する。各場面が別年の設定なら明示し、同一年なら日付/曜日を揃える。矛盾探しのゲームで無関係な暦の矛盾を残さない。
- 本編の詐欺4・正常2は既定を維持してよいが、正答率だけでなく見逃し/誤警報を分ける。正常問題を難しくするため曖昧にするのは避ける。
- ヒント利用者の正答には「比較対象を教えた」支援が含まれる。ヒントなし能力と同一視しない。ヒントが解答そのものを明かす必要はない。

### 7.4 ドキュメントの整合

`docs/難易度ルーブリック.md`には「16問」「事前/事後各5問」、旧タグ、Brier、RTが長いほど難しいという旧記述が残る。現状は評価問題18問＋練習1、順序尺度の確信度、RTの多義性を認める分析計画である。`docs/project.md`の一次指標も「詐欺4本のRT短縮」等のまま。今回これらの意思決定資料を勝手に変更せず、最新計画との整合を修正候補として提案する。
