# 分析計画（データ収集前に固定）

作成：2026-09-30（2026-10-10 更新、2026-10-04 版の扱いを追記）／対象：contentVersion `2026-10-10`（10/3）と `2026-10-11`（10/4〜）、schemaVersion 5
再現用スクリプト：`analysis/select_sample.py`（除外基準の適用）→ `analysis/analyze_primary.py`（主要・副次評価）。本計画の方法はこの2つに実装されている。
本計画はパイロット前に固定する。パイロットで変更した場合は変更点と理由を追記し、本実験の開始前に再固定する（本実験開始後は変更しない）。

## 1. 研究設問と主張の範囲
- 設問：体験型ゲーム（現実情報とデジタル情報の照合）をプレイした後、詐欺／正常の判断の正確さは向上するか。
- デザイン：単群の事前・事後比較。事前/事後のテストは並行フォームA/Bをセッションごとにランダムに割り付ける（カウンターバランス）。
- **主張しないこと**：3D であることの優位性（非3D教材との比較をしていない）、長期的な定着・被害の抑制（遅延テストなし）、ゲームだけの因果効果（練習効果・テスト慣れと分離できない）。これらは限界として明記する。
- **事前テストの位置づけ**：参加者は事前テストの前に、募集ポスター（大学祭の掲示）とゲームのタイトル画面・同意画面で「部屋の情報とスマホの通知を見比べる」ことを知る。事前得点は「何の説明も受ける前の能力」ではないため、手続きに掲示と開始前の説明を記載する（掲示の最終版は手元の `docs/poster/poster_A1.pdf` に保存。答えや見分け方のコツは載せていない）。

## 2. 主要指標
- **事前→事後のテスト正答数の変化**（各6問：詐欺3・安全3）。
- 正答数と合わせて、**見逃し率**（詐欺を正常と答えた率）と **誤警報率**（正常を詐欺と答えた率）を分けて報告する。全部「詐欺」と答えるだけでも一部は正解になるため、正答率だけで判断しない。
- **主要評価は「事前→事後の正答数の差」の1つだけ**とする。以下の副次指標はすべて探索的に扱う。
- 検定：Wilcoxon 符号順位検定（両側、α=.05）。6問の離散得点で同順位・差0が多いため、`scipy.stats.wilcoxon(post, pre, zero_method="pratt", method="approx", correction=False)`（差0も順位付けに含める Pratt 法・正規近似・連続性補正なし）に固定する。**全員の差が0の場合は検定せず「変化なし」と報告**する。
- 効果量：**対応のある順位双列相関 r_rb**（差0を除いた符号付き順位の差÷順位和）を主とし、参考として r = Z/√N（Z は上記の正規近似の値、N は差0を含む参加者数）を併記する。
- 推定：差の平均と 95% 信頼区間。**参加者の事前・事後のペアをまとめて再標本化**するブートストラップ（10,000 回、乱数 seed = 20261103、パーセンタイル法）。事前・事後のどちらかが6問そろわない参加者は主解析から除外し、除外数を報告する。
- 有意差が出なかった場合も、推定値・区間・限界を報告する。
- **天井効果の扱い（事前に固定）**：事前テストで満点（6/6）だった人の割合を報告し、満点の人は伸びしろがないことを限界として書く。主要評価は上記のまま全員で行い、結果を見てから満点の人を除いたり問題を差し替えたりしない。参考として「事前が満点でない人」に限った差を併記してよい（探索的）。
- 検出力の目安：対応のある t 検定の近似では N=30 で d ≈ 0.53 以上に 80% の検出力。これは Wilcoxon（同順位の多い離散得点）の検出力を保証するものではない。小さい効果は「検出できなかった」と書き、「効果がない」とは書かない。

## 3. 副次指標（探索的に扱う）
- **d′ と判断基準 c**（信号検出理論）：各3問しかないため、ヒット率・誤警報率が 0 や 1 になる。**Hautus（1995）の log-linear 補正**（ヒット数+0.5、試行数+1）を全員に一律で適用する。1問で率が約33ポイント動くため、個人別の値は不安定であり、集団平均の参考値として扱う。
- **ゲーム本編**：正答数、見逃し・誤警報、関係するオブジェクトを両方調べた割合（`viewedAllRelevant`）、ダミーを調べた数、ヒントの使用率とタイミング、調べ直し（`judgeOpenCount`≥2）。
  - ヒントは schemaVersion 5 から探索画面の「💡 ヒント」ボタンのみ（判定画面には見たヒントの文面だけを表示）。タイミングは `hintAtScenarioMs`（シナリオ開始から）。旧定義の `hintAtMs`（判定画面起点）は常に空。ヒント利用者の正答には「比較対象を教えた」支援が含まれるため、ヒントなしの能力と同一視しない。
  - S1（不在通知）の判定に必要な情報は「メモ（公式サイト）＋スマホ」（カレンダーの在宅予定は補助情報）。
  - `viewedAllRelevant` は「開いた」ことの記録であり、「理解した」ことの証拠ではない。
  - 調査ごとの表示時間 `dwellMs` は「パネルを開いていた時間」で、読んだ時間ではない。2026-10-10 から、調査パネルを開いたまま本編の画面を離れた場合は離れた時点で閉じた扱いにする（それ以前は戻ってきた時点で閉じたため、離れていた時間が含まれた）。アプリ切替などの非表示時間は dwellMs から差し引かれない。
  - 各問の開始時に「第n問」の案内が約2.2秒表示される（表示中も操作できる）。**探索時間（シナリオ開始→初回調査）と `hintAtScenarioMs` にはこの表示時間が含まれる**。本編RT（初回調査→決定）には含まれないため、RT から一律に差し引かない。
  - 窓の外は空・雲・揺れる枝葉だけの中立な景色のループ映像（2026-10-02 追加、10-03 にくっきり見えるよう調整。表示のみの変更のため版は上げない）。全問で共通、時刻・季節・天気は読み取れないようにしており、判定の手がかりにはならない。映像を再生できない端末では静止画になる。
  - 本編は詐欺4・安全2のため、全部「詐欺あり」と答えても 4/6 正解になる。本編の正答率を単独の成果指標にしない。
- **反応時間（RT）**：短くなったことだけを成果としない（慣れ・端末差・読み飛ばしが混ざる）。必ず正答率と並べて示す。画面が非表示だった時間（`hiddenMs`）が30秒以上ある試行はRTの分析から除く。
- **確信度（1〜5）**：確率尺度ではないため、Brier スコアなどには変換しない。正答・誤答ごとの確信度の分布と、「確信度4以上の誤答」の数を報告する。
- **自己効力感**（事前・事後の単一項目）、**学習実感・没入感・難しさ**（各単一項目）。
- **SUS**（日本語版10項目、得点0〜100）：操作性の指標であり、学習効果の指標ではない。項目は「システム」を「このゲーム」に置き換えた改変版であることを明記し、妥当性確認済みの尺度とは書かない。

## 4. 項目・フォームの扱い
- フォームA/Bの難易度タグの一致は等価性の証明ではない。**フォームの割付順（A→B / B→A）を要因に入れた分析**（割付順ごとの伸びの比較）を行い、差があれば報告する。
- ランダム割付は人数の均等を保証しないため、割付ごとの人数を報告する。
- 事後テストには本編と題材が近い問題（家族のなりすまし、パスワード変更、URLの偽装）が含まれる。**近い転移**として扱い、「まったく新しい場面への転移」とは書かない。
- フォームの対応関係：F2（URLの偽装）は A/B とも「公式と同じ文字列の後に別ドメインが続く」構造にそろえた。一方、**S2 は A＝二段階認証コード、B＝パスワード変更通知で必要な知識が異なり、F1 も A＝ニセ警察、B＝家族なりすましで異なる**。カウンターバランスで平均化はされるが個々のフォームの等価性は保証しないため、割付順別の結果を必ず報告する。テストは選定した判断課題の成績であり、全手口の習得度を測るものではない。
- 項目分析：各問の正答率（.2〜.8 を目安）と **項目－残余相関**（その項目を除いた同じ段階の合計との相関）。フォームごとに回答者が分かれるため、各項目の n も示す。正答率 .9 超／.1 未満の項目は報告のうえ、次の版で差し替えを検討する。5〜8名のパイロットだけで尺度の妥当性が確立したとはしない。

## 5. 除外基準（分析前に機械的に適用：select_sample.py）
1. `testRun = true`（開発・テスト用のプレイ）、および `playMode = free`（2回目以降の自由プレイ。事前/事後テストがなく研究用データとは別に収集。export は既定で除外）
2. 同意なし（`consent_agreed` が false）、または `completed` でない（途中まで回答した人は、完了した段階までの記述統計のみに使う）。**未同意のデータは研究分析に使わない**
3. `validate_export.py` で ERROR が出たセッション（原因を記録）
4. 所要時間が 3 分未満（読まずに進めた疑い）
5. 途中で配信が更新された（版の混在）、または本収集の対象版でない
6. 担当者記録で除外と判断したもの（参加者コードで照合。例：本人の2回目と確認、操作を大きく手伝った、途中で交代）。除外理由は sessionId ごとに `sample/inclusion.csv` に残す
- **再プレイ（`priorPlays` ≥ 1）は自動では除外しない**：学祭の共用端末では別人の初回プレイでも1以上になるため。スタッフの記録（端末ごとの参加者）と照合し、同一人物の2回目と確認できたものだけ除外する。感度分析として「`priorPlays`=0 のみ」の結果も併記する。
- 再読み込み（`resumeCount`≥1）やアプリ切替（`hiddenMs`）のあるセッションは除外せず、該当試行のRTのみ除外する。本編のRT（初回調査→決定）と同じ区間の非表示時間は `hiddenAfterFirstInspectMs`。
- 2026-10-09 以降、本編の途中でブラウザの「戻る」等で別の画面へ行き、同じページのまま本編へ戻った場合は、同じ試行として続ける（ヒント・調査の記録とRTの起点を保持）。別の画面にいた時間は RT に含まれ、非表示時間としては記録されない。再読み込みした場合は従来どおり、その問題をやり直し `restarted = true`。テストでは `restarted = true` の回答、本編では `restarted = true` の試行がRT除外の対象。
- 本人が「はじめて」を選んでも `priorPlays` ≥ 1 の場合は、スタッフ記録と照合して扱いを決める（自動除外はしない）。
- 2026-10-09 以降、この端末に過去のプレイ記録がある状態で「はじめて遊ぶ」を押すと確認画面が出る。`firstTimeConfirmed = true`（本人がはじめてと回答）／`null`（確認なし＝端末で初回）。確認画面で「2回目以降」を選んだ人は自由プレイになり研究データに入らない。
- 練習ラウンドは 2026-10-09 から判定・ヒントまで体験する（記録なし・正解なし・手がかりは含まない）。自由プレイは練習を省略できる（`t_practiceSkipped`）。

## 6. 版の管理
- `contentVersion` が異なるデータは合算しない。パイロット（形成的評価）のデータは本実験の分析に含めない。
- **本収集の開始時に、コードのコミット（git の短いハッシュ）・contentVersion・`analysis/items.json`・本計画を記録して保存する**。集計結果を見てから除外条件や問題を選び直さない。
- 途中で配信が更新されたセッション（`contentVersionsSeen` が2つ以上）は版の混在として除外する。本番期間中は配信を更新しない。
- 結果画面の「みんなとの比較」の匿名集計（stats/festival2026）は表示用であり、研究の人数・統計には使わない（検証済みセッションから算出する）。
- タイプ診断・レーダーチャートは参加者向けの演出で、研究の指標には使わない。
- 限界として記載：セッションログの書き込みは認証なし（読み取りは禁止）。学祭規模・ID推測の困難さから実害は小さいと判断した。

### 6.1 本収集中の版の更新（2026-10-04 追記・主要評価の結果を見る前に固定）
- 初日（10/3、版 `2026-10-10`）の利用で操作上の課題が見つかったため、2日目の展示前に版 `2026-10-11` を配信した。変更は**操作とチュートリアルだけ**：段階式の操作練習（1手順＝1動作）、視点操作をスワイプ＋「正面に戻す」＋感度切替に変更（右スティック廃止）、移動スティックを小さく高い位置へ、**各問の開始で位置と向きを初期位置に戻す**、本編第1問だけ進め方の手順表示、文字の拡大、スクロールの合図、引っぱり更新の防止、Android の向き固定ボタン。**問題・ヒント・解説・採点・事前事後テスト・ログ項目は同一**（`analysis/items.json` は版番号以外同じ）。
- この追記の時点で確認したのは、初日の件数・完了率・所要時間・本編RTの中央値など**記録の健全性だけ**で、主要評価（事前→事後の正答数）の結果は見ていない。
- **主要評価（事前→事後の正答数の差）は両版を合わせて分析する**（テストと本編の問題が同じで、変更は操作だけのため）。あわせて、**版を説明変数に加えた結果と、版ごとの結果を感度分析として併記**する。版によって結論が変わる場合はその旨を報告する。
- **本編の行動指標（探索時間・判断時間・調べた物・ヒントのタイミング・dwellMs）は版ごとに分けて報告し、合算しない**（操作方法と各問の開始位置が違うため）。
- 練習の所要時間（practiceStart→practiceEnd）も版で意味が変わるので、版ごとに分ける。
- 除外基準の適用：`python analysis/select_sample.py <出力> --content-version 2026-10-10,2026-10-11 [--staff 記録.csv]`。配信の切り替えをまたいだセッション（`contentVersionsSeen` が2つ）は従来どおり「版の混在」で除外。
- 限界として記載：感度の設定・「正面に戻す」の使用は記録していない。版の割り付けは日付で決まり（ランダムではない）、来場者の層が日によって異なりうる。
- **同じ版の中での案内表示の調整（2026-10-04 02:21 JST 配信、配信元 `870d512`・公開コミット `c5c8b2e`）**：版 `2026-10-11` のまま、案内の表示だけを変えた。
  - 練習で段階をクリアするたびに中央に「できた！」と表示する。
  - 見回す段階で感度の説明を出す。手の合図の動きを変える。ヒントの×を大きくする。
  - 端末（PC・Android・iOS）に合わせて操作説明の文言を変える。
  - 本編2問目以降は、画面下の操作説明と、調査・判定・解説の「下にスクロール」の合図を出さない（練習と第1問だけ表示）。
  - 問題・手順・採点・ログ項目は同じなので、**版は分けない**。
  - 配信の前後はセッションの開始時刻で区別できる。本編の行動指標について、配信の前後に分けた結果を参考として併記する。
  - 2問目以降の合図がないことで、長い解説を最後まで読まない人が増える可能性がある。これは限界として記載する。

## 7. 報告する記述統計
参加者数（除外前後と除外理由ごとの件数）、年齢層・職業の分布、所要時間（中央値・範囲）、フォーム割付ごとの人数と成績、保存・同期の欠損件数。
- 主解析の単位は参加者。1人が12問答えても、回答数を標本数として扱わない。
- 結果章の構成：参加者の採否と欠損 → 対応のある成績変化 → 見逃し/誤警報と確信度 → 確認行動 → 使用体験。
