# 分析計画（データ収集前に固定）

作成：2026-09-30／対象：contentVersion `2026-10-01`、schemaVersion 2
本計画はパイロット前に固定する。パイロットで変更した場合は変更点と理由を追記し、本実験の開始前に再固定する（本実験開始後は変更しない）。

## 1. 研究設問と主張の範囲
- 設問：体験型ゲーム（現実情報とデジタル情報の照合）をプレイした後、詐欺／正常の判断の正確さは向上するか。
- デザイン：単群の事前・事後比較。事前/事後のテストは並行フォームA/Bをセッションごとにランダムに割り付ける（カウンターバランス）。
- **主張しないこと**：3D であることの優位性（非3D教材との比較をしていない）、長期的な定着・被害の抑制（遅延テストなし）、ゲームだけの因果効果（練習効果・テスト慣れと分離できない）。これらは限界として明記する。

## 2. 主要指標
- **事前→事後のテスト正答数の変化**（各6問：詐欺3・安全3）。
- 正答数と合わせて、**見逃し率**（詐欺を正常と答えた率）と **誤警報率**（正常を詐欺と答えた率）を分けて報告する。全部「詐欺」と答えるだけでも一部は正解になるため、正答率だけで判断しない。
- 検定：対応のある比較として Wilcoxon 符号順位検定（両側、α=.05）。効果量は r（=Z/√N）と、正答数の差の平均とその 95% 信頼区間（ブートストラップ 2,000 回）を示す。
- 検出力の目安：N=30 の対応あり比較で、80% の検出力が得られるのは効果量 d ≈ 0.53 以上。これより小さい効果は「検出できなかった」と書き、「効果がない」とは書かない。

## 3. 副次指標（探索的に扱う）
- **d′ と判断基準 c**（信号検出理論）：各3問しかないため、ヒット率・誤警報率が 0 や 1 になる。**Hautus（1995）の log-linear 補正**（ヒット数+0.5、試行数+1）を全員に一律で適用する。1問で率が約33ポイント動くため、個人別の値は不安定であり、集団平均の参考値として扱う。
- **ゲーム本編**：正答数、見逃し・誤警報、関係するオブジェクトを両方調べた割合（`viewedAllRelevant`）、ダミーを調べた数、ヒントの使用率とタイミング、調べ直し（`judgeOpenCount`≥2）。
  - `viewedAllRelevant` は「開いた」ことの記録であり、「理解した」ことの証拠ではない。
  - 本編は詐欺4・安全2のため、全部「詐欺あり」と答えても 4/6 正解になる。本編の正答率を単独の成果指標にしない。
- **反応時間（RT）**：短くなったことだけを成果としない（慣れ・端末差・読み飛ばしが混ざる）。必ず正答率と並べて示す。画面が非表示だった時間（`hiddenMs`）が30秒以上ある試行はRTの分析から除く。
- **確信度（1〜5）**：確率尺度ではないため、Brier スコアなどには変換しない。正答・誤答ごとの確信度の分布と、「確信度4以上の誤答」の数を報告する。
- **自己効力感**（事前・事後の単一項目）、**学習実感・没入感・難しさ**（各単一項目）。
- **SUS**（日本語版10項目、得点0〜100）：操作性の指標であり、学習効果の指標ではない。項目は「システム」を「このゲーム」に置き換えた改変版であることを明記し、妥当性確認済みの尺度とは書かない。

## 4. 項目・フォームの扱い
- フォームA/Bの難易度タグの一致は等価性の証明ではない。**フォームの割付順（A→B / B→A）を要因に入れた分析**（割付順ごとの伸びの比較）を行い、差があれば報告する。
- ランダム割付は人数の均等を保証しないため、割付ごとの人数を報告する。
- 事後テストには本編と題材が近い問題（家族のなりすまし、パスワード変更、URLの偽装）が含まれる。**近い転移**として扱い、「まったく新しい場面への転移」とは書かない。
- 項目分析：各問の正答率（.2〜.8 を目安）、点双列相関。正答率 .9 超／.1 未満の項目は報告のうえ、次の版で差し替えを検討する。

## 5. 除外基準（分析前に機械的に適用）
1. `testRun = true`（開発・テスト用のプレイ）
2. 同意なし、または `completed` でない（途中まで回答した人は、完了した段階までの記述統計のみに使う）
3. `validate_export.py` で ERROR が出たセッション（原因を記録）
4. 所要時間が 3 分未満（読まずに進めた疑い）
- **再プレイ（`priorPlays` ≥ 1）は自動では除外しない**：学祭の共用端末では別人の初回プレイでも1以上になるため。スタッフの記録（端末ごとの参加者）と照合し、同一人物の2回目と確認できたものだけ除外する。感度分析として「`priorPlays`=0 のみ」の結果も併記する。
- 再読み込み（`resumeCount`≥1）やアプリ切替（`hiddenMs`）のあるセッションは除外せず、該当試行のRTのみ除外する。

## 6. 版の管理
- `contentVersion` が異なるデータは合算しない。パイロット（形成的評価）のデータは本実験の分析に含めない。

## 7. 報告する記述統計
参加者数（除外前後）、年齢層・職業の分布、所要時間（中央値・範囲）、フォーム割付ごとの人数、保存・同期の欠損件数。
